## 1. プロジェクト概要

| 項目 | 内容 |
|---|---|
| プロダクト名(仮題) | 『久遠寺邸の一夜 〜大正浪漫脱出奇譚〜』 |
| ジャンル | 一人称ポイント&クリック型 3D 脱出ゲーム |
| プラットフォーム | Web ブラウザ(PC 推奨・スマートフォン対応) |
| 描画技術 | Three.js(WebGL2) |
| 舞台 | 大正十年・春。和洋折衷の豪華な洋館(全3部屋) |
| 部屋構成 | リビング(応接間)/ 寝室 / 書斎 |
| 想定プレイ時間 | 20〜40分 |
| エンディング | 単一(全プレイヤーが必ず脱出できる) |
| 言語 | 日本語 |

## 2. 背景と目的

Three.js を用いたブラウザ完結型の脱出ゲームを制作する。
「大正浪漫」の美術と物語性を備えつつ、**誰も途中で詰まない**上質な謎解き体験を提供することを最重要目的とする。

## 3. コアコンセプト(3本柱)

1. **絶対に詰まない** — 進行構造(依存グラフ)・アイテム設計・3段階ヒントの三重の仕組みで、論理的に「脱出不能」が発生しない設計にする。さらに自動全行程クリアテストで機械的に保証する。
2. **ギミックの多様性** — 同型の謎を繰り返さない。探索・観察・火(あぶり出し)・機構操作・鏡文字・計数・ダイヤル錠・旋律再現・整列・消灯(夜光)・回転機構・アイテム結合・総合(金庫)の13系統を採用する。
3. **大正浪漫の空気** — 和洋折衷の調度、電球色の照明、オルゴールの音色、優しいミステリーの物語で「その時代にいる」感覚を作る。ホラー演出は行わない。

## 4. ターゲットとプレイ環境

| 項目 | 内容 |
|---|---|
| ターゲット | 謎解き初心者〜中級者(脱出ゲーム初体験でも完走できる) |
| 対応ブラウザ | Chrome / Edge / Safari / Firefox 各最新版 |
| 必須要件 | WebGL2(非対応環境では案内画面を表示) |
| PC | 中位ノート PC で 60fps を目標 |
| モバイル | タッチ操作フル対応、30fps 以上(横持ち推奨・縦持ち可) |
| 入力 | マウス / タッチのみで完走可能(キーボード不要) |

## 5. ゲーム仕様サマリ

- 部屋中央の定点からドラッグ(スワイプ)で360°見回し、気になる場所をクリック(タップ)して調べる方式。
- ギミック(柱時計・ピアノ・金庫など)は専用の注視ビューにズームインして操作する。
- アイテムはインベントリで管理。選択して対象に使う/アイテム同士を結合する/3Dで拡大して細部を調べられる。
- 入手した手紙・日記などの文書はいつでも再読できる(「おぼえがき」機能)。メモを取らなくても解ける。
- 時間制限・ゲームオーバー・ランダム要素なし。オートセーブで常に再開可能。

詳細は `02-game-design.md`(世界観・UI・美術・音)と `03-puzzle-design.md`(全ギミック仕様)に定義する。

| FR-09 | アイテム拡大 | 3D 回転ビューで細部を読み取れる |
| FR-10 | アイテム結合 | 2つのアイテムを組み合わせる(例: 破れた写真) |
| FR-11 | 専用ギミック UI | 柱時計 / ピアノ / 宝石箱 / 本棚 / 地球儀 / 金庫 / 照明スイッチ / 暖炉 |

| FR-16 | リザルト | クリア時間・ヒント使用回数・称号表示、「もう一度遊ぶ」 |
| FR-17 | データリセット | 「はじめから」で確認の上セーブを初期化 |
| FR-18 | 演出スキップ | 長尺演出は短縮できる |
| FR-19 | モバイル対応 | タッチ操作・レイアウト最適化 |

## 7. 非機能要件

| ID | 分類 | 要件 |
|---|---|---|
| NFR-01 | **詰み不可能性(最重要)** | 進行を止める袋小路が構造上存在しないこと。`03-puzzle-design.md` の詰み防止設計規則に準拠し、自動全行程クリアテストを CI の必須ゲートとする |
| NFR-02 | 難易度 | 全ギミックは3段階ヒントの最終段に従えば必ず突破できる。体感難度「やさしめ〜ふつう」。1つの謎の想定思考手数は3手以内 |
| NFR-03 | プレイ時間 | 標準 20〜40分(ヒント使用時は短縮方向) |
| NFR-04 | 性能 | PC 中位機 60fps / モバイル 30fps 以上。初回ロード 5秒以内(4G 相当) |
| NFR-05 | アセット自給 | 外部 3D モデル・画像・音源ファイルに依存しない(全て手続き生成)。軽量かつ権利クリーン |
| NFR-06 | アクセシビリティ | 無音でも完走可能(音の謎に視覚代替)/ 色のみに依存する謎なし(色名併記・形状差別化)/ クリック操作のみで完走可能 |
| NFR-07 | セーブ堅牢性 | 保存データはスキーマ検証(zod)。破損検出時は安全に案内して初期化 |
| NFR-08 | コード品質 | TypeScript strict / 不変データ構造 / 小さなファイル分割 / コアロジックのテストカバレッジ 80% 以上 |
| NFR-09 | 互換性 | 対応ブラウザ最新版で動作。WebGL2 非対応時はフォールバック案内 |
| NFR-10 | 表現配慮 | ホラー・ジャンプスケアなし。急激な明滅(光過敏)を避ける |

## 8. スコープ外(本バージョンでは作らないもの)

- マルチエンディング / 分岐シナリオ
- 多言語対応(将来拡張の余地は残す)
- VR / ゲームパッド対応
- オンライン要素(ランキング・マルチプレイ)
- 外部アセットストアの 3D モデル・音源の利用

## 9. 制約・技術前提

- 技術スタック: Vite + TypeScript(strict) + Three.js(最新安定版) + zod。UI フレームワークは使わず素の DOM + CSS。
- 開発補助: Vitest(ユニット / 統合)、Playwright(E2E)、ESLint + Prettier。
- テクスチャは Canvas による手続き生成、ジオメトリは Three.js プリミティブの組み合わせ、効果音・BGM は Web Audio API 合成。
- フォントはシステム明朝体(ヒラギノ明朝 / 游明朝)を使用し、Web フォントは読み込まない。

## 10. 受け入れ基準

| ID | 基準 |
|---|---|
| AC-01 | 自動全行程クリアテスト(初期状態 → 玄関開放)が CI で成功する |
| AC-02 | 全ギミックに3段階ヒントが実装され、最終段の通りに操作すれば必ず進行する |
| AC-03 | 到達可能な任意のゲーム状態から脱出状態へ到達できる(不可逆な袋小路がないことのテストで担保) |
| AC-04 | リビング・寝室・書斎の3部屋と玄関脱出、`03-puzzle-design.md` 記載の必須ギミック全種が動作する |
| AC-05 | 中位ノート PC で 60fps、初回ロード 5秒以内 |
| AC-06 | ミュート状態でクリア可能。色情報単独に依存する謎がない |
| AC-07 | 美術チェックリスト(02文書 §7)の大正意匠要素を満たす |

## 11. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| 手続き生成アセットの表現力不足 | 見た目の品質低下 | 実在洋館(旧岩崎邸等)を参照した形状ディテールの優先度付け、照明・ポストプロセスによる底上げ。素材は差し替え可能な Factory 構造にする |
| モバイル性能不足 | フレームレート低下 | 画質プリセット(影解像度・ポストプロセス段階制御) |
| 合成音のチープさ | 雰囲気を損なう | 重要音(オルゴール・チャイム)に FM 合成+リバーブを重点投資。AudioProvider を抽象化し将来差し替え可能に |
| スコープ肥大 | 完成遅延 | ギミックは 03 文書の一覧で固定(単一情報源)。追加は磨きフェーズ以降に判断 |
| ブラウザ差異 | 特定環境で不具合 | E2E を Chromium / WebKit の両系統で実行 |
